# RS 다이나믹스 — 실데이터 연결본

S&P500 실데이터를 받아 스크리닝하고, 그 결과를 앱이 읽는 JSON 한 장으로 떨어뜨린다.
기존 `us_screener_dashboard_sp500` 계열의 사양을 그대로 옮겼고, 노트북은 건드리지 않았다.

## 돌리는 법

```bash
pip install yfinance pandas numpy lxml

python run_sp500.py --limit 60     # 먼저 60종목으로 확인 (5분쯤)
python run_sp500.py                # 전체 500종목
```

끝나면 `app.html` 이 갱신된다. 더블클릭하면 열린다.

옵션:

| 옵션 | 뜻 |
|---|---|
| `--limit N` | 앞 N종목만. 처음엔 이걸로 확인 |
| `--rs-min 80` | RS 하한 (기본 80) |
| `--no-fundamentals` | 실적 수집 생략. 가장 느린 구간이라 급할 때 |
| `--refresh` | 당일 캐시 무시하고 새로 받기 |

가격·실적은 `cache/` 에 날짜별로 남는다. 같은 날 다시 돌리면 네트워크를 타지 않는다.
전체 실행은 실적 수집 때문에 처음 한 번은 20~30분 걸린다. 그다음부터는 캐시가 받쳐준다.

## 파일

| 파일 | 역할 |
|---|---|
| `run_sp500.py` | 파이프라인 진입점. 테마 딕셔너리도 여기 있다 |
| `fetch_data.py` | 네트워크 전담. 공급자를 바꿀 때 **이 파일만** 갈아끼운다 |
| `screener_live.py` | 스크리닝 엔진 — RS·트렌드템플릿·패턴 5종·지지선·4분면 |
| `snapshot_export.py` | 파워플레이·U/D볼륨·어닝반응·베이스카운트 + JSON 직렬화 |
| `app_template.html` | 앱 원본. UI를 고칠 땐 여기를 고친다 |
| `app.html` | 데이터가 주입된 실행본 |
| `test_pipeline.py` | 네트워크 없이 도는 통합 테스트 |
| `android/` | WebView 셸 |

## 엔진에 들어간 것

* **RS 레이팅** — IBD 가중 성과(63일 0.4 / 126·189·252일 각 0.2) → 유니버스 백분위 1~99
* **트렌드 템플릿** — 미너비니 8조건, 조건별 통과 여부까지 계산
* **패턴 5종** — VCP · W · 역헤숄 · 하향추세선 돌파 · 파워플레이.
  넷은 서로 독립으로 돌고 지그재그 감도도 따로 준다. 중복 적중 시
  VCP → W → 역헤숄 → 추세선돌파 → 파워플레이 순으로 하나만 대표로 뽑는다.
* **4분면** — 장기 RS 백분위 × 단기 RS(RS선 21일 변화율) 백분위.
  y축은 표시 대상 종목들 안에서 다시 계산해 중앙값으로 나눈다. 궤적은 1~4주 전 좌표를
  같은 방식으로 되돌려 계산한 것이라 진짜 이동 경로다.
* **데이터 위생** — 중복 날짜 병합 → ffill(5봉) → 커버리지 90% 미만 행 제거 → RS 표본 붕괴 경고.

## 실데이터 첫 실행 때 볼 것

`[스크린] 유니버스 500 · RS≥80 100 · 패턴 적중 N` 줄이 나온다.

* RS≥80 이 100 근처면 정상이다 (상위 20%). 이게 몇 개면 가격 행렬이 깨진 것이다.
* 패턴 적중이 0이면 파라미터가 빡빡한 것이다. `PatternParams` 의
  `pivot_within`(0.25)과 `vcp_max_last_depth`(0.15)부터 만져보면 된다.
